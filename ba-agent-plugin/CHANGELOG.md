# Changelog

## 1.9.0
- **Gaps are filed by status and move on their own.** `gaps/open/` (asked, answered later, reopened, carried forward), `gaps/deferred/` and `gaps/resolved/`, each with `md/GAP-nnn.md` and `json/GAP-nnn.json`. A gap is written to `gaps/open/` the moment it is found; when it is answered and closed it moves to `gaps/resolved/`; deferring moves it to `gaps/deferred/`, revisiting moves it back. Stories already worked this way (`candidates` -> `approved` / `unapproved` / `deferred`). The register is now `state/gap-register.json` (machine state, not a user folder). Projects from 1.8.x are migrated when opened: the register moves to `state/`, each gap is filed by status, and the old `gaps/md` / `gaps/json` copies are removed only after the new ones are written. `validate` warns when a gap's copy is missing or in two folders; `recover` rebuilds them. Every `gap` command returns `gap_file` (where the gap lives now).
- **Closing a gap is one step.** `gap resolve` no longer needs a closer, a closure summary or a confirmation when the decision owner gave the answer: the owner is recorded as closer and their own words as the confirmation (audit `closer_basis: DECISION_OWNER_ANSWER`). If someone else answered, the core refuses with `IDENTITY_REQUIRED` until the owner confirms. Material gaps, conflicts and incomplete answers are checked exactly as before. The gap-resolution skill no longer asks "shall I close it?" or for the closer's name and role.
- **`baseline confirm` defaults to the decision owner** as approver (audit `approver_basis`); a different approver is still named when the user says so.
- **`START-HERE.md`** at the top of the project folder: where the project stands in plain words, the decision owner, and a table of every folder with its count and a link - rebuilt after every writing command.
- **`find` command** (needs no project): lists BA projects and likely BRDs in a folder, so `/ba-agent:start` proposes the BRD and folder in one question instead of asking for paths. PDF, DOC, RTF and XLSX BRDs are no longer a dead end: the error tells Claude to read the file itself, save a faithful Markdown copy under `source/` and `init` that, telling the user in one line.
- **Skills and `/ba-agent:start`:** requirements and gap analysis run straight through after `init` (nothing to ask) and report in one line what was saved and where; file messages are one line, not a ceremony before every dialog; a new non-negotiable keeps the PM from being asked anything the core can find out.
- Tests: 300 (new `test_gap_folders/`, `test_cowork/`, and the ADR suite). Includes ADR items below.

### ADR log (also in 1.9.0)
- **`ADR-LOG.md` at the top of every artifact folder and the project root.** A table of who approved or decided what and when (IST): gap closures and decisions, answers, reopened gaps, carry-forwards, decision-owner and policy changes, baseline and story approvals, deferrals, changes requested, BRD change decisions. Each folder lists only its own events (e.g. `stories/approved/ADR-LOG.md` lists story approvals); the root lists all of them. It is a view of `state/audit.jsonl`, rebuilt after every writing command, so it cannot drift - do not edit it.
- **`json/` is now named in every save receipt.** `files_saved` carries the parent `folder` (the one holding `md/`, `json/` and `ADR-LOG.md`), and the skills tell the user that folder instead of only the `md/` path, so the `json/` records are no longer easy to miss.
- Tests: 4 new in `test_adr/`.

## 1.8.0
- **Fix: `/ba-agent:triage-stories` no longer dead-ends after `/ba-agent:triage-gaps`.** Resolving a gap marks the baseline stale, and a stale baseline made every story ineligible, so each dialog offered only *Keep as is* / *Defer*. `story triage` now returns `preflight` - the problems that block *every* story (stale or unconfirmed baseline, pending BRD review) - once, with the step that clears them, and the command clears them first in one dialog (`baseline create` -> `Confirm vN` / `Not now`). Rows list only their own blockers; `eligible_after_preflight` says which stories unblock.
- **Stories flagged by a resolved gap get `Update story`.** The dialog offers it (and `No change needed` when the cause is not a resolved gap); the card shows the **Decision to apply** (the validated interpretation of the closed gap), so the edit can be written without fetching anything else. A story blocked by an open gap offers neither `Update` nor `Approve`.
- **Context engineering.** Each stage now reads only what it needs:
  - *Prompt surface:* `gap-resolution` (21 KB) and `story-review` (10 KB) are lean loops plus on-demand `references/` (`actions`, `validate-and-resolve`, `revisit`, `triage`). `human-approval` (7 KB) keeps only the cross-cutting rules; skill descriptions (always loaded) are half the size; `change-detection` loads only when `changes check` reports a change. A gap session loads about 10.6 KB up front instead of 40.3 KB (-74%), a story session 10.7 KB instead of 29.5 KB (-64%); the triage commands -67% / -46%.
  - *Presentation built by the core (`present`):* `gaps next` and `story next` return a ready `AskUserQuestion` `dialog`, a compact `card` and a numbered `fallback`. The model relays them instead of composing them, so output is consistent and cheaper. Options follow the rules in code (e.g. `Approve vN` is withheld while a story cannot be approved).
  - *No duplicate summary:* a gap whose dialog already carries priority, question, why, source and affected requirements is sent as **the dialog alone** (`inline: true`) - no extra chat message. Queue lists are one `summary` line, not a table. Stories still send the card (acceptance criteria must be readable) and then the dialog.
  - *Lean CLI output:* compact JSON with empty values omitted (`--pretty` for humans); gap packets no longer embed the `explain` block (use `gap explain`), the full requirement bodies or the repeated owner; `story next` returns the card, not the raw story with its review history (`--full` / `story show` on demand); `files_saved` lists only the folders a command changed. Typical results are 26-82% smaller (`owner set` -74%, `gaps triage` -62%, `gap resolve` -57%, `story triage` -48%, `baseline create` -82%).
  - *Delegation:* `init` / `source outline` return per-section sizes, `batches` and `delegate`; large BRDs go to the `requirement-analyst` / `gap-analyst` / `story-builder` helpers, which return at most 8 lines and a file, so the main session never holds the BRD.
  - *Save check without a second tool call:* `files_saved` is a fresh disk scan taken after the write, so the model no longer re-lists the folder just to repeat it.
- Tests: `tests/test_context/` (26 tests) cover the dialog rules, the triage dead end, lean packets, compact output, receipt deltas, BRD batching, dangling-reference detection across the split skills, and byte budgets for prompt files and CLI results. `tests/measure_efficiency.py` now reports the prompt surface and CLI output sizes. No schema or on-disk change; existing projects open unchanged. Plugin version 1.8.0.
- Behaviour notes: the gap packet's `explain`, `options`, `impacted_requirements`, `evidence`, `why_it_matters`, `previous_answers` and `decision_owner` moved out (the card, `gap explain` and `owner show` carry them); `story next` returns the raw story only with `--full`; `story triage` rows no longer carry `location` or the global blockers.

## 1.7.0
- **Medium/Low gaps can be carried forward all at once.** Before the first MEDIUM/LOW gap the agent now asks one question - *Go through each* or *Carry all forward* - so a user who wants to bypass them no longer answers a prompt per gap. Choosing *Go through each* keeps the one-gap-at-a-time dialog; the question is not repeated in the same round, and not asked in `/ba-agent:triage-gaps`.
- Core: `gaps carry-forward-all --by-name --by-role [--reason]` carries every eligible gap (MEDIUM/LOW, non-material, open or presented) forward under the same rules as `gap carry-forward`: each gap keeps its own `carry_forward` record and `GAP_CARRIED_FORWARD` audit event, plus one `GAP_CARRIED_FORWARD_BULK` event. CRITICAL/HIGH, material, deferred and answered-later gaps are never touched and are returned in `not_carried`. A named person and a decision owner are still required (`IDENTITY_REQUIRED`, `OWNER_REQUIRED`); `NOTHING_TO_CARRY_FORWARD` if none is eligible. `gaps next` returns `bulk_carry_forward` (`offer_now`, `eligible_gap_ids`, `count`).
- Skills/docs: `gap-resolution`, `choice-prompts`, `human-approval`, `cli-reference`, user guide and README describe the choice. No schema or on-disk change. Plugin version 1.7.0.

## 1.6.0
- **`md/` and `json/` subfolders in every artifact folder.** Readable copies now live in `md/` and machine records in `json/`, so a folder is no longer a mix of both: `atomic-requirements/`, `gaps/`, `decisions/`, `baselines/`, `extracted/`, `changes/` and each of `stories/{candidates,approved,unapproved,deferred,archive}/`. Example: `stories/approved/md/US-001.md` and `stories/approved/json/US-001.json`. `state/`, `snapshots/` and `reports/` are unchanged.
- **Existing projects migrate on open.** Loose `.md`/`.json`/`.jsonl` files from the old layout are moved into the new subfolders (byte for byte, idempotent). A loose file that differs from the one already in the subfolder is never overwritten; it stays where it is.
- **Every stage proves its files are saved.** Every writing command now returns `files_saved` (folder, `md/` and `json/` paths, file counts); `req commit` returns `readable_folder`, `json_folder` and `files_on_disk`; `story approve` / `request-changes` return `location` (the real on-disk path) and `saved_to` (absolute). New read-only command `files` lists every artifact folder and its counts at any time.
- **Skills:** new `ba-workflow/references/save-checkpoint.md` and non-negotiable 9 — after each stage the agent checks the files with its own file tools and tells the user the full folder paths before asking them to review or approve (requirements, gaps, baseline, candidate, approved and unapproved stories). The user no longer has to ask for files to be copied.
- Tests: 244 (9 new in `test_layout/`: path mapping, populated md/json folders at every stage, receipt, migration of a flat project, no overwrite of a conflicting loose file, CLI `files_saved` / `files`).

## 1.5.0
- **Change detection and impact analysis** for the BRD and for approved user stories (new skill `change-detection`, command `/ba-agent:changes`, core group `changes`).
  - **Snapshots + hashes:** the extracted BRD text of every accepted version is stored in `snapshots/brd/`; every approved story version is stored with its material/content/approval hashes and an immutable copy in `snapshots/stories/`. The original BRD is still only ever read.
  - **Detection:** BRD additions, modifications and deletions per section with the old/new lines; approved stories edited by hand (JSON or the readable `.md`), approval fields altered, deleted, unreadable or dropped into `approved/` without an approval — plus the BA Agent's own edits. Runs at pipeline start/resume, before gap/story triage and before artifacts are rewritten (the core refuses with `CHANGES_UNREVIEWED` until a material change has been shown and applied).
  - **Explain first:** `changes check` (alias `source check`, now side-effect free) records a change (`changes/CHG-nnn.md|json`) with what changed, when, affected requirements / open gaps / decisions to re-validate / linked and approved stories / baseline, and the required actions. `changes apply` (named person + their words) then marks affected artifacts stale: requirements `NEEDS_REVIEW`, gaps and stories flagged with the change id, baseline stale. Approvals are never invalidated without a recorded reason and decisions are only listed for re-validation.
  - **Material vs formatting-only:** layout/markup/whitespace/re-wrapping (BRD) and whitespace/Markdown decoration (stories) are accepted automatically, recorded and audited with no review. A changed word or number is always material. An agent `story edit` that does not change meaning keeps the approved version and approval.
  - **Manual edits are never discarded:** applying one restores exactly what was approved, keeps the edit verbatim (`snapshots/stories/*.observed-CHG-nnn.*`) and turns it into the next `CANDIDATE` needing re-approval; `story revert-edit` discards an unapproved edited version (archived), `story restore` brings back a deleted approved story, `story history` lists every approved version with approver and wording. Story ids of deleted stories are not reused.
  - **Reconciliation:** each record tracks items (requirements, source acceptance, new sections, gaps, baseline, stories, re-approval, story removal) closed by the real work and evaluated from live artifacts; `complete` stays PARTIAL until every record is reconciled; `status`, `trace --write` (new *Change impact* section) and `validate` report it.
- Fixes: a bytes/formatting-only BRD refresh now also updates each requirement's `source_fingerprint` (it previously left a `validate` error); `gaps commit --cross-pass-done` clears the impact flag on gaps whose requirements were reassessed.
- Schemas: new `change`; `workflow_state.source.material_fingerprint`. Existing projects open unchanged (BRD snapshot is stored on the first check while the BRD still matches; approved stories are adopted). Plugin version 1.5.0.

## 1.4.0
- **`/ba-agent:triage-gaps`** — lists every `OPEN` (presented, answered later, reopened, carried forward) and `DEFERRED` gap in review order with priority, deferral reason / actor / date / revisit date, decision owner and who it waits on, linked requirements and stories, and whether it blocks stories; then reviews them one at a time with the existing gap dialog: answer (validated for completeness and conflicts before anything resolves), explain, defer, carry forward (MEDIUM/LOW only), or keep as it is.
- **`/ba-agent:triage-stories`** — lists every unapproved story (pending review, not approved, deferred) with version, readiness, open gaps, deferral reason or earlier note, and whether it can be approved right now (`eligible` / `blockers`); reviews them one at a time: approve, edit (new version, back for approval), defer, not approved, or keep as is. Deferred stories stay in `stories/deferred/` and are listed again next time.
- Both commands are thin: they list and present, then call the existing actions, so validation, IST audit history, versioning, traceability and resume are unchanged. Same command files and skills in Claude Code and Claude Cowork (numbered-list fallback where `AskUserQuestion` is unavailable). `/ba-agent:review` stays as the general “continue where I left off” router and now delegates to the two triage flows; `/ba-agent:status` points to them.
- Core: `gaps triage [--status OPEN|DEFERRED]`, `gaps next --id GAP-ID` (a DEFERRED or carried-forward gap is shown unchanged until the human decides to answer it), `gap keep ID` (open gap = Answer Later; deferred / carried gap untouched, audit `GAP_TRIAGE_KEPT`); `story triage`, `story next --id` now finds a story in any pending folder, `story keep ID` (audit `STORY_TRIAGE_KEPT`). Gap packets also carry `deferral`, `carry_forward`, `skipped_count` and `revisit_needed_to_answer`, and DEFERRED / carried gaps offer `Keep Deferred` / `Keep Carried Forward`.
- Story lifecycle: `story defer` also accepts a *not approved* story (`CHANGES_REQUESTED → DEFERRED`), and `story revisit` also brings a *not approved* story back to review at the same version (it is not an approval; `approve` on `unapproved/` without a revisit is still refused). Audit events record `from_status`.
- No schema or on-disk format change; existing projects load unchanged. Plugin version 1.4.0.

## 1.3.0
- **Carry Forward for MEDIUM/LOW gaps** (`gap carry-forward ID --by-name --by-role [--reason]`): the gap stays `OPEN` (never resolved, no decision created), stops blocking baseline and story generation, and is recorded with the person who chose it, the decision owner, an `Asia/Kolkata` timestamp and an optional reason (audit event `GAP_CARRIED_FORWARD`; `carry_forward` / `carry_forward_history` on the gap). **Not allowed** for CRITICAL/HIGH gaps or any `material` gap (security, compliance, scope/policy, critical business rules): `CARRY_FORWARD_NOT_ALLOWED`; the existing blocking rules still apply, and a carried gap that becomes ineligible blocks again (`validate` warns). Open, answered-later and deferred gaps still block exactly as in 1.2.0 — only an explicit Carry Forward (or the existing project-wide `policy set --carry-forward`) lifts the block.
- **Gap dialog by gap type** (packet `options`, `carry_forward_allowed`): MEDIUM/LOW non-material gaps offer *Suggested Answer* (only with an evidence-backed `suggested_answer`), *Other*, *Explain This Question*, *Carry Forward*; CRITICAL/HIGH/material gaps keep *Other*, *Explain This Question*, *Answer Later*, *Defer This Gap*. The Cowork numbered-list fallback carries the same choices.
- **Suggested Answer** (`gap answer ID --use-suggestion`): records the cited suggestion as the human's answer (`basis: SUGGESTED_ANSWER`, `suggestion_source`), then validates it like typed text; it never resolves a gap by itself. **Explain This Question** (`gap explain ID`): returns the missing information, why it matters and the impact on the requirements (audit `GAP_EXPLAINED`); records no answer.
- **Revisit:** `gaps next --carried` / `gap revisit ID` ask a carried gap again (history kept; `GAP_CARRY_FORWARD_REVISITED`). `gaps next` no longer re-asks carried gaps. `gap resolve` reports `was_carried_forward` and `stories_to_update`.
- **Story traceability and readiness:** every story declares `unresolved_decisions` (one entry per open gap on its requirements: potential impact, readiness effect, optional interim assumption) and gets a derived `readiness` (`READY_FOR_DEVELOPMENT` / `NEEDS_CLARIFICATION` / `NOT_READY`). The core refuses stories that omit an open gap, link a gap that is invented or already resolved, or lack a potential impact. `story gaps --requirements …` lists what to declare. Story Markdown shows the readiness and an *open, not an approved decision* section; interim assumptions are labelled *not approved* and never enter `decision_ids`. Stories saved before 1.3.0 are brought under the rule when edited.
- **Update on resolution:** resolving a carried gap flags every story that named it (including approved ones) for impact review and marks the baseline stale; refresh the baseline, then `story edit` (a new version that goes through review again; the approved version stays in force until then). `confirm-unaffected` is refused while a story still names a resolved gap. A new gap opened for requirements that already have stories flags those stories too.
- **Baseline / status / trace / complete:** baseline requirements carry `open_gap_ids` and carried gaps are marked in the outstanding list; `status` and `report` list carried gaps and stories needing clarification / not ready; `trace` has an open-gap → story table and `stories_missing_open_gap_links`; a `NOT_READY` story keeps `complete` PARTIAL.
- Schemas: `gap` (`carry_forward`, `carry_forward_history`), `story` (`unresolved_decisions`, `readiness`). New gaps/stories only; existing projects load unchanged. Plugin version 1.3.0.

## 1.2.0
- **Simpler gap dialog, same for every gap:** `Other` (free-text answer or instruction), `Explain This Question`, `Answer Later`, `Defer This Gap`. The separate "Provide an answer" option and **Carry forward** are removed (the per-gap `gap carry-forward` command was never released and is gone; the existing project-wide `policy set --carry-forward` is unchanged). A suggested answer is shown only when the gap cites supporting evidence (`suggested_answer {answer, source}`), in the chat message, never as an option.
- **Answer Later** (`gap answer-later`, `gap skip` kept as an alias): no reason needed; the gap stays `OPEN` in the outstanding queue and is asked again; `status` lists it. Audit event `GAP_ANSWER_LATER`.
- **Defer This Gap** (`gap defer`): a reason and the name and role of the person deferring are now mandatory (`REASON_REQUIRED`, `IDENTITY_REQUIRED`); the decision owner, an `Asia/Kolkata` timestamp and the reason are recorded in the gap and in the `GAP_DEFERRED` audit event; status `DEFERRED`. Revisit date (`YYYY-MM-DD`, not in the past) is optional unless `policy set --deferral-revisit-required CRITICAL,HIGH` says otherwise (default: not required). Deferred gaps whose date has arrived are surfaced by `gaps next` and `status`; `gap revisit` keeps earlier deferrals in `deferral_history`.
- **Validated answers only:** the advisory conflict check now also compares an answer with the BRD excerpts of the impacted requirements; a later clarifying answer marks the earlier conflict `CLARIFIED`. Resolution still needs a complete, conflict-free, reviewed answer (unchanged `gap resolve` rules).
- **Blocking:** unresolved CRITICAL/HIGH gaps block as before; unresolved *material* (compliance-sensitive) gaps now also always block, even when the non-blocking policy was accepted. Open, answered-later and deferred gaps all keep blocking. One shared rule (`blocks_requirements`) is used by baseline, status and story approval.
- **Interruption safety:** a status change is saved together with the id of its audit event; if the session stops between the two, `validate` warns and `recover` restores the event with its original IST time, actor and reason (idempotent).
- **Priority in the gap dialog:** the `AskUserQuestion` for each gap starts with its priority (`[HIGH priority] …`). **"Explain This Question"** is a request for help, not an answer: Claude explains the gap in plain language with a real-world example, then shows the dialog again. Where `AskUserQuestion` is unavailable (e.g. Cowork) the same four choices are offered as a numbered list.

## 1.1.0
- Atomic requirements are now saved in a clearly named `atomic-requirements/` folder (was `requirements/`). Existing projects are migrated automatically the next time they are opened. `req commit` now returns `saved_to` and `files_on_disk`, and the skill tells the user the folder path and verifies it exists.
- Default project folder is the folder that contains the BRD (the attached folder in Cowork) instead of a nested `ba-output/<name>`.
- Gap resolution presents one gap at a time, as an `AskUserQuestion` prompt with a text box (plain-chat fallback). `gaps next` now defaults to one gap.
- Stories marked *not approved* are now saved in their own `stories/unapproved/` folder (previously they stayed in `candidates/` with a status flag). Old projects are migrated on open; `story next --unapproved` revisits them; `status` and `validate` count them.
- Choice dialogs: the full gap/story is shown as a normal chat message and the `AskUserQuestion` dialog carries only a short plain-text question with described options (new `references/choice-prompts.md`: limits, result handling, fallback).
- Story review works the same way: one story per `AskUserQuestion` prompt with a text box. The user types *approve*, their suggestions (→ new story version, re-presented), or *not approved* (→ `story request-changes`, kept out of `approved/`).

## 1.0.0 — 2026-10-22
Initial release implementing `ba_agent_plugin_implementation_v2.md`.

- Plugin: manifest, 3 commands (`start`, `status`, `review`), 10 skills, 5 optional agents.
- Deterministic stdlib-only core (`scripts/ba.py`): stage/gap/story state machines, schemas, stable IDs, source fingerprints and section outline (md/txt/docx), verbatim-quote verification, safe/atomic writes with path containment, append-only IST audit log.
- Decision-owner preflight; closure record (closer, role, owner, respondent, decision link, `closed_at_ist` `+05:30`, validation) written through a recoverable journal; `recover` rolls interrupted closures/approvals forward.
- Answer conflict detection (advisory pre-check + mandatory explicit review), confirmed-change flow with requirement versioning, decision supersession and impact flags.
- Versioned baselines with strict blocking policy; stories only from an approved baseline; approve/edit/defer/revisit with exact-version approvals.
- Source-change detection with section-level impact assessment.
- 80+ automated tests (unit, workflow, crash-recovery, safety, CLI end-to-end).
