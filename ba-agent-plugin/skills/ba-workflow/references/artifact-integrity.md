# Artifact integrity (shared reference)

**Layout** (all under the confirmed project folder; the supplied requirements stay where they are): every artifact folder holds two subfolders, `md/` (readable copies) and `json/` (machine records), and no loose files: `index/` (`md/requirements-index.md`, `json/requirements-index.json`: a read-only locator over the supplied files) · `enriched/` (**generated** copy of each requirement file at the same relative path: the source text byte for byte, a one-line header and, under each requirement, a block with its approved acceptance criteria, open gaps and readiness) · `gaps/{open,deferred,resolved}/` (each with `md/GAP-nnn.md` and `json/GAP-nnn.json`; a gap moves folders as its status changes; the register is `state/gap-register.json`) · `decisions/` (`json/decision-log.jsonl`, `md/DEC-*.md`) · `acceptance/{candidates,approved,unapproved,deferred,archive}/` (one record per requirement, each with `md/` and `json/`, named after its key) · `changes/` (`md/CHG-nnn.md`, `json/CHG-nnn.json`) · `snapshots/source/` (the exact bytes of every accepted version of each requirement file) and `snapshots/ac/` (every approved version) · `reports/` · `START-HERE.md` and `ADR-LOG.md` at the top (generated views, never edited) · `state/workflow.json`, `state/gap-register.json`, `state/enriched-manifest.json`, `state/audit.jsonl`, `state/pending/`, `state/backups/`, `state/inbox/`.

**Rules**
1. The JSON records are authoritative; the `.md` files are rendered views. Never hand-edit anything under `state/`, `index/`, `gaps/`, `decisions/`, `acceptance/` or `snapshots/`. Change them only through the core so schemas, transitions and audit events stay consistent.
2. **The supplied requirement files are read-only input.** No code path writes them; the project folder cannot be inside them. A requirement text change is made upstream and picked up by `changes check`.
3. **`enriched/` is generated, never hand-edited, and never an input.** It is a pure function of the accepted source snapshot, the approved criteria and the gap state: removing the BA blocks from a copy gives the source back byte for byte (the core checks this before every write and keeps the old copy if it fails). A copy edited by hand is not overwritten silently: `changes check` keeps the edit and records it (an edited approved criterion becomes the next version for review; other text is restored). A file carrying BA markers is refused as a source (`ENRICHED_FILE_AS_SOURCE`). `doc check` shows each copy as IN_SYNC, STALE, MISSING or DRIFT; `doc sync` re-renders.
4. `state/audit.jsonl` and `decisions/decision-log.jsonl` are append-only.
5. Writes are atomic (temp file + replace); previous versions of overwritten derived files are kept in `state/backups/`. `safe_write.py` is the only way to create helper files, and only under `state/inbox/` or `reports/`.
6. Criteria are **versioned**; older versions stay in history (`acceptance/archive/`, `snapshots/ac/`). Nothing is deleted.
7. An interrupted gap closure leaves a journal in `state/pending/`. `validate` flags it; `recover` rolls it forward idempotently (the enriched copies can always be regenerated, so they need no journal). Run `recover` before continuing if `status` says so.
8. Run `validate` (and `trace`) before presenting candidate criteria and before reporting completion. Report failures; do not paper over them.
9. If a write fails (permissions, disk), report it, keep the item pending, and do not tell the user it was saved.
10. A project created by ba-agent 1.x answers `LEGACY_PROJECT`: it is not migrated; say so and keep it on 1.10.2.
