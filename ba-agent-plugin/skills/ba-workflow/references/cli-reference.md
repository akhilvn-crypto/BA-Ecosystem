# Core CLI reference

`python "${CLAUDE_PLUGIN_ROOT}/scripts/ba.py" [--root DIR] [--args-file FILE.json] <group> <action> [options]`
`--args-file`: JSON object whose keys are option names (`-` or `_`), overriding CLI values. Use it for any text with quotes/newlines/unicode. Files for `--file` are JSON arrays/objects (see skills).

| Command | Purpose / key options |
|---|---|
| `init --brd FILE --root DIR [--name N] [--copy-source]` | Create project, fingerprint + outline the BRD (md/txt/docx). Stage → `BRD_PARSED`. `--copy-source` copies (never moves) the BRD into `source/`. |
| `status [--json]` | Stage, counts, blockers, validation, **NEXT** action. |
| `files` | Read-only: every artifact folder that has files, with the absolute `md/` and `json/` paths and file counts. Every writing command also returns the same as `files_saved`. |
| `validate` · `trace [--write]` · `recover` · `complete` · `report` | Integrity checks · coverage/orphans/dupes · roll forward interrupted work · finish or report PARTIAL · write summary. |
| `source section SID [--allow-changed]` · `source outline` | Fetch ONE section's text (context-efficient) / list sections. |
| `changes check [--no-record]` (alias `source check`) | Compare the BRD with its accepted snapshot and every approved story with what was approved. Returns `changes` (records `CHG-nnn`: what changed, `classification` MATERIAL/FORMATTING_ONLY, `impact`, `required_actions`), `formatting_only_accepted`, `awaiting_reconciliation`, `warnings`. **Changes nothing downstream** except accepting formatting-only differences (recorded). Runs automatically before guarded commands. |
| `changes apply [--id CHG-nnn] --by-name --by-role --statement` | After the user has seen the impact: BRD change → requirements `NEEDS_REVIEW`, gaps/stories flagged, baseline stale; edited approved story → approved version restored, edit kept as next `CANDIDATE`; deleted story → recorded. Needs identity + their words. |
| `changes list [--status S]` · `changes show ID` · `changes status` · `changes dismiss ID --item ITEM --reason R --by-name --by-role` | Register · one record · detected/open/stale overview (read-only) · close a `new_section` or `story_removal` item with a reason. |
| `source accept --by-name --by-role --statement` · `source history` | Accept the reassessed BRD (stores the new BRD snapshot) · list stored BRD versions. |
| `req add --file reqs.json` | Items: `title, statement, type, source_section_ids[], source_excerpt (verbatim), actors, preconditions, outcomes, constraints, dependencies, acceptance_info, assumptions, flags`. Returns IDs + advisory duplicate/conflict flags. |
| `req commit` · `req pairs` · `req list [--status]` · `req show ID` | Validate decomposition → `REQUIREMENTS_READY` · cross-requirement candidates. |
| `req update ID --file changes.json --reason R --cause decision\|source-change\|correction [--decision-id D] [--by-name --by-role]` | New requirement version (old kept). |
| `req confirm ID --note N` · `req remove ID --reason R --by-name --by-role` | After BRD change: still valid / dropped (kept as `REMOVED`). |
| `owner set --name N --role R [--gap GAP-ID] [--statement S]` · `owner unknown --choice pause\|analysis-only` · `owner show` | Decision owner (default or per-gap). |
| `gaps add --file gaps.json` | Items: `category` (taxonomy), `title, description, evidence, why_it_matters, question, impacted_requirement_ids[], priority CRITICAL\|HIGH\|MEDIUM\|LOW, priority_rationale, material?, suggested_answer? {answer, source}` (only with cited evidence) |
| `gaps commit --cross-pass-done` · `gaps next [--limit 1] [--carried]` · `gaps list [--status S]` | Finish analysis · present gaps (**needs owner**; each packet has `options`, `carry_forward_allowed`, `explain`; carried-forward gaps are not re-asked unless `--carried`) · list (with `carried_forward`). |
| `gap show ID` · `gap answer ID --response T [--respondent-name --respondent-role]` · `gap answer ID --use-suggestion` | Store raw answer (or the gap's evidence-backed suggested answer, `basis: SUGGESTED_ANSWER`); returns `candidate_conflicts`. Never resolves anything. |
| `gap explain ID` | **Explain This Question**: facts for the explanation (missing information, why it matters, impact on requirements); audit `GAP_EXPLAINED`; records no answer. |
| `gap carry-forward ID --by-name N --by-role R [--reason T]` | **Carry Forward** (MEDIUM/LOW, non-material only; else `CARRY_FORWARD_NOT_ALLOWED`): gap stays `OPEN`, stops blocking stories, records actor/decision owner/IST time (audit `GAP_CARRIED_FORWARD`). Baseline marked stale. |
| `gap followup ID --answer-id A1 --note N` · `gap conflict ID --answer-id A1 --with REQ-003,DEC-001 --description D` | Incomplete answer · record a conflict. |
| `gap resolve ID --answer-id A1 --interpretation T --closed-by-name N --closed-by-role R --closure-summary S --confirmation "<closer's words>" [--conflict-status PASSED\|CHANGE_CONFIRMED] [--reviewed IDS] [--conflicting IDS --change-by-name --change-by-role --change-statement T --requirement-updates FILE] [--owner-confirmation T]` | The only way to `RESOLVED`. Writes decision + IST audit event atomically (journaled). |
| `gap answer-later ID` (alias `gap skip`) | **Answer Later**: no reason; gap stays `OPEN` in the outstanding queue (`skipped_count`, audit `GAP_ANSWER_LATER`). |
| `gap defer ID --reason R --by-name N --by-role R [--revisit-by YYYY-MM-DD] [--owner WAITING_ON]` | **Defer This Gap**: reason and actor mandatory; revisit date mandatory when policy says so. Records actor, decision owner, IST time, reason → `DEFERRED` (audit `GAP_DEFERRED`). Deferred ≠ resolved. |
| `gaps triage [--status OPEN\|DEFERRED]` | **Triage list** (read-only): every unresolved gap that is `OPEN` (presented, answer-later, reopened, carried forward) or `DEFERRED`, in review order, with priority, deferral reason/actor/date/revisit date, decision owner, linked requirements and stories, `blocks_stories`, `due_for_revisit`. |
| `gaps next --id GAP-ID` | Present one chosen gap (used by triage). `OPEN` → `WAITING_FOR_ANSWER`; **DEFERRED or carried-forward gaps are returned unchanged** (`revisit_needed_to_answer`); needs the decision owner. |
| `gap keep ID` | Triage "keep it": an open gap = *Answer Later*; a deferred / carried-forward gap is left untouched and only the decision is audited (`GAP_TRIAGE_KEPT`). |
| `gap revisit ID` · `gap reopen ID --reason R --by-name --by-role` | Deferred or carried-forward → ask again (earlier deferral/carry-forward kept in `deferral_history` / `carry_forward_history`; audit `GAP_CARRY_FORWARD_REVISITED`) · reopen a resolved gap. |
| `policy set [--carry-forward true\|false] [--deferral-revisit-required CRITICAL,HIGH\|none] --by-name --by-role --statement T` | Human-accepted policy: non-blocking (MEDIUM/LOW, non-material) unresolved gaps may stop blocking; priorities whose deferral needs a revisit date. |
| `baseline create [--summary S]` · `baseline confirm --version N --by-name --by-role --statement T` · `baseline show [--version N]` | Versioned baseline (`PROPOSED` → human `APPROVED`). Unchanged inputs are reused. |
| `story gaps --requirements REQ-001,REQ-002` | The unresolved gaps a story for these requirements must declare (question, why it matters, carried-forward, blocking). Run it before writing stories. |
| `story add --file stories.json` | Items: `title, user_story{role,capability,value}, acceptance_criteria[] ("Given…when…then…"), requirement_ids[], dependencies, assumptions, notes{business_rules,validation_exceptions,non_functional}, unresolved_decisions[{gap_id, potential_impact, readiness_effect NEEDS_CLARIFICATION or NOT_READY, interim_assumption?}]` — one entry per open gap touching the story (`UNRESOLVED_DECISION_MISSING` otherwise). The core derives `open_gap_ids` and `readiness`. |
| `story next [--id US-001] [--deferred] [--unapproved] [--batch N]` · `story show ID` | Present for review (marks `IN_REVIEW`). Default is one story: show it in chat, then ask in a short `AskUserQuestion` with a text box (approve / suggestions / not approved). `--unapproved` lists stories in `stories/unapproved/`. |
| `story triage` | **Triage list** (read-only): all unapproved stories (`candidates/`, `unapproved/`, `deferred/`) in review order with version, status, readiness, open gaps, deferral reason / last note, `eligible` and `blockers` (what `approve` would refuse for). |
| `story next --id US-ID` | Present one chosen story from any folder; moves nothing except marking a `CANDIDATE` as `IN_REVIEW`. |
| `story keep ID` | Triage "keep as is": no change, decision audited (`STORY_TRIAGE_KEPT`). |
| `story approve ID --version N --statement "<human words>" [--approver-name --approver-role]` | Exact version; writes to `stories/approved/`. |
| `story edit ID --file changes.json --reason R` | New version → needs new approval. Editable: title, user_story, acceptance_criteria, requirement_ids, dependencies, assumptions, notes, unresolved_decisions. Recomputes open gaps and readiness. |
| `story history ID` · `story restore ID --reason R --by-name --by-role` · `story revert-edit ID --reason R --by-name --by-role` | Every approved version with approver, words and snapshot · bring back a deleted approved story from its snapshot · discard an unapproved edited version (manual or agent), keeping the approved version in force. |
| `story defer ID --version N [--reason R]` (pending **or not-approved** story → `stories/deferred/`) · `story revisit ID` (deferred **or not-approved** story → back to review at the same version; not an approval) · `story request-changes ID --version N --note N` (saves to `stories/unapproved/`) · `story confirm-unaffected ID --statement S` | Review lifecycle / clear an impact flag. |

Common `error.code`s: `OWNER_REQUIRED`, `OWNER_UNKNOWN`, `IDENTITY_REQUIRED`, `MISSING_METADATA`, `NOT_PRESENTED`, `ANSWER_INCOMPLETE`, `CONFLICT_REVIEW_REQUIRED`, `CONFLICT_UNRESOLVED`, `AWAITING_OWNER_CONFIRMATION`, `REQUIREMENT_UPDATE_REQUIRED`, `CLOSURE_IN_PROGRESS` (run `recover`), `EXCERPT_NOT_FOUND`, `UNSUPPORTED_FORMAT`, `SOURCE_CHANGED`, `SOURCE_CHANGED_AGAIN`, `CHANGES_UNREVIEWED` (show the change, then `changes apply`), `CHANGE_RECORD_STALE` (re-run `changes check`), `NOT_APPLICABLE`, `UNKNOWN_CHANGE`, `UNKNOWN_ITEM`, `NOT_DISMISSABLE`, `NOTHING_TO_RESTORE`, `NOTHING_TO_REVERT`, `SNAPSHOT_UNAVAILABLE`, `STORY_NOT_CAPTURABLE`, `IMPACT_REVIEW_PENDING`, `BASELINE_STALE`, `REQUIREMENT_BLOCKED`, `ACCEPTANCE_FORMAT`, `VERSION_MISMATCH`, `APPROVAL_EVIDENCE_REQUIRED`, `OPEN_GAPS`, `CARRY_FORWARD_NOT_ALLOWED`, `ALREADY_CARRIED_FORWARD`, `NO_SUGGESTED_ANSWER`, `UNRESOLVED_DECISION_MISSING`, `UNRESOLVED_DECISION_RESOLVED`, `UNKNOWN_GAP_LINK`, `WRITE_FAILED`, `CLOCK_UNRELIABLE`, `PATH_ESCAPE`, `SOURCE_PROTECTED`.
